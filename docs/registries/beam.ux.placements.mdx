# Entry file placements

`beam.ux.placements` holds the named **file placement** strategies. A placement derives the disk path
an entry's file lands at when it is mirrored to a filesystem, for example a git-tracked directory you
want entry bodies committed to. It decides where the file goes on disk and nothing else: an entry's
URL comes from its containment tree, never from its placement.

## What ships

- `default` composes the entry's namespace (dots become slashes), its type, its slug and the
  codec's extension: `marketing/page/pricing.mdx`.
- `date-partitioned` files by creation date under a root, `articles` unless
  `beam.ux.placement.date_root` says otherwise: `articles/2026/11/launch-notes.mdx`.

## Adding a strategy

Implement `FilePlacement`, whose one method returns the path for an entry, and register it by name:

```php
use Splicewire\Beam\Ux\Placement\PlacementResolver;

app(PlacementResolver::class)->register('by-author', new ByAuthorPlacement);
```

## How an entry's placement is chosen

Most specific first:

1. The entry's own `placement_ref`, naming a registered strategy.
2. The `beam.ux.placement.namespaces` config map, a namespace prefix to strategy name, matched by the
   longest prefix. `['articles' => 'date-partitioned']` files every `articles.*` entry by date.
3. An entry imported from disk keeps its original relative path.
4. `default`.

A name in the reference or the map that isn't registered throws, rather than quietly falling back.
