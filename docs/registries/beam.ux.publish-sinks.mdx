# Publish sinks

`beam.ux.publish-sinks` holds the **sinks** a published Release is projected to: a record of the
publication outside its database. Each entry is a `PublishSink`, keyed by its name.

## What a sink is, and is not

The database pin is the publication, and it is not a sink. A sink is a projection of it:

A sink works in two phases, and the registry owns the boundary of both:

- **Freeze.** `project()` is called inside the publish transaction, once a member kind has published,
  with that kind's `ReleaseProjection`, in its own savepoint. The sink records there what it will
  project. If it throws, its savepoint rolls back and the publication carries on.
- **Project.** `project()` returns a closure (or null). The registry runs it once the publication
  commits, never for a Release that rolled back. If it throws, the registry reports it and runs the
  next sink's projection anyway; the publisher still gets its result.

So a failed sink never fails the publication, and never stops another sink. A sink records its own
failure where its readers look. A sink does not register its own after-commit work: that would run
outside the registry's containment.

## What ships

- `git` records the Release's mirror files in the local Git repository in one commit, through the
  frozen recording receipt (ADR-0226). It projects entry members.

## Adding or replacing a sink

```php
use Splicewire\Beam\Ux\Release\Sinks\PublishSinkRegistry;

app(PublishSinkRegistry::class)->register(new AuditTrailSink);
```

Registering under a taken name replaces that sink, in its place.
